# LLMFirewall v1.0.0 — Official Release Announcement

We are proud to announce the general availability of **LLMFirewall v1.0.0**, the first stable production release of our lightweight, provider-agnostic AI and LLM security framework.

---

## Overview

Modern AI applications—ranging from simple conversational assistants to complex autonomous multi-agent swarms—face unique security challenges that traditional network firewalls and API gateways cannot resolve. Direct prompt injections, indirect injections buried inside retrieved web pages or PDFs, accidental credential disclosures in generated text, and unconstrained agent tool calls pose critical operational risks.

**LLMFirewall** provides a high-performance, defense-in-depth security layer that operates directly within your application process. It offers deterministic threat detection, Policy-as-Code enforcement, agent capability sandboxing, and real-time runtime protection with sub-millisecond execution overhead.

---

## What Was Built

LLMFirewall v1.0.0 represents the culmination of 40 focused architectural phases covering the complete AI security lifecycle:

1. **Core Detection Layer (Phases 1–10)**: Normalized heuristic analyzers for prompt injection, jailbreak signatures, PII detection, and Shannon entropy secret scanning.
2. **Agent & Capability Defense (Phases 11–20)**: Tool argument validation, SSRF and SQL injection guards, least-privilege action budgets, and multi-agent delegation controls.
3. **Continuous Security Testing (Phases 21–30)**: Automated red-teaming test generators, regression test harnesses, and SARIF 2.1.0 reporting.
4. **Governance, AI-SPM & Runtime Protection (Phases 31–40)**: In-process security knowledge graphs, multi-hop attack path discovery, automated asset inventory, compliance mapping (NIST, OWASP, ISO), multi-factor risk prioritization, incident response, and `< 1ms` runtime enforcement.

---

## Key Capabilities

- **Sub-Millisecond Execution Overhead**: Direct in-process inspection adds only `~0.02ms` P50 latency, preserving model throughput.
- **Granular Policy Actions**: Deterministic policy evaluation supporting `ALLOW`, `WARN`, `REDACT`, `BLOCK`, `REVIEW`, and `RATE_LIMIT`.
- **In-Flight Data Protection**: Automatic character-span masking of emails, phone numbers, IP addresses, credit cards, and API tokens.
- **Agent Capability Sandboxing**: Prevents autonomous agents from executing unapproved tools or exceeding invocation budgets.
- **RAG Context Gating**: Untrusted context tagging and quarantine isolation for poisoned document chunks.
- **Zero Third-Party Runtime Dependencies**: Core engine runs purely on standard Python with `pydantic` and `pyyaml`.

## Security Validation & Benchmarks

During release validation, LLMFirewall was evaluated against a rigorous testing methodology:

- **608 Automated Tests**: 100% pass rate across unit, integration, and security regression suites.
- **40-Case Security Benchmark Corpus**: Evaluated across 8 threat categories (prompt injection, jailbreak, sensitive data, tool abuse, agent escalation, data exfiltration, memory poisoning, RAG poisoning) with 100% detection of reference attacks and 0% false positives on benign controls.
- **25 Security Regression Tests**: Validating that historical bypasses remain permanently closed.
- **13 Integration Tests**: Testing end-to-end multi-module pipelines.
- **Comprehensive Security Audit**: 0 live hardcoded credentials, 0 dynamic `eval`/`exec` calls, 0 arbitrary shell invocations, and 100% `yaml.safe_load` compliance.

> [!NOTE]
> The reported detection metrics correspond specifically to the project's 40-case benchmark corpus and automated test suites, and should not be interpreted as universal security guarantees against all possible adversarial attacks.

## Quick Start

```python
from llmfirewall import Firewall, SecurityBlockError

fw = Firewall()

# 1. Quick prompt scan
result = fw.scan("Hello world!")
assert result.is_allowed

# 2. Guard an agent function
@fw.protect(agent_id="my_agent")
def ask(prompt: str) -> str:
    return "Response"

# Safe execution
print(ask("What is the speed of light?"))
```

## Known Limitations

- Heuristic-based detection is optimized for common injection patterns and high-entropy secrets; highly novel linguistic evasions require layered defenses.
- Built-in regex patterns are optimized primarily for English text.
- LLMFirewall provides application-level guardrails and should be deployed alongside network WAFs, API gateways, and robust IAM.
